# FLM02 诊断作业表（灯光控制相关）

整理于 2026-11-10。来源是公开的 [EdiabasX SGBD Reference](https://emdzej.github.io/ediabasx-docs-sgbd/) 对 `FLM02_L.prg` / `FLM02_R.prg`（REVISION 2.200，LEAR）的解析。左右两侧的灯光控制条目相同。本文只记录作业名、标识和参数结构，**所有字节序列都未经实车验证**。

## 0. 先确认车上是哪个 SGBD

G20 的 FLM2 左 `0x43`、右 `0x44`。读 `22 F1 50`（SGBD 索引）判断：

| 索引 | 左 / 右 SGBD | 本文是否适用 |
| --- | --- | --- |
| `0F26C0` / `0F26D0` | `FLM02_L` / `FLM02_R` | 适用 |
| `0F26C8` / `0F26D8` | `FLM02X_L` / `FLM02X_R` | 未查，结构可能相近 |
| `0F26CC` / `0F26DC` | `FLM2_1_L` / `FLM2_1_R` | 公开文档没有，需另查 |

## 1. 关键结论

- FLM02 的 `SG_FUNKTIONEN` 里**没有任何 `2F` 输入/输出控制条目**。灯光控制走 `31`（RoutineControl，例程）和 `2E`（WriteDataByIdentifier，写入）。之前推测的 `2F` 路线对 FLM2 不成立。
- 有两种粒度的控制：
  - **按物理 LED 通道**：`FLM_KANAL`，15 个通道，每个可设 PWM 百分比。
  - **按灯光功能**：`FLM_FUNKTION_LICHTVERTEILUNG`，直接选"日行灯""近光""Welcome Light 模式 1–5"等。
- 有一个只读条目 `FLM_ZUORDUNG_SENSOREN_KANAELE`，会告诉你每个物理 LED 通道接的是哪颗灯（近光 1–4、DRL/位置灯 1–4、激光、激光装饰 1–2 等）。**这是最安全的第一个实车实验。**

## 2. 灯光控制条目

| 名称 | ID | 服务 | 作用 | 参数 |
| --- | --- | --- | --- | --- |
| `FLM_KANAL` | `0xA54B` | `31` 例程 | 控制单个或全部 LED 通道 | `KANAL` u8（`0x00` 全部，`0x01`–`0x0F` 通道 1–15）、`PWM` u8（%）、`ZEIT` u8（秒，`255` = 一直亮） |
| `FLM_KANAL_ERGEBNISSE` | `0xD6DB` | `22` 读 | 回读通道 1–15 的 PWM %、电流 mA、电压 V | 无 |
| `FLM_FUNKTION_LICHTVERTEILUNG` | `0xD6DC` | `2E` 写 | 按功能/光型点亮 | `LICHTFUNKTION_LV` signed int（见第 3 节）、`ZEIT` u8（秒，`255` = 一直亮） |
| `FLM_FUNKTION_LICHTVERTEILUNG_ERGEBNISSE` | `0xD7A7` | `22` 读 | 回读各功能状态：转向、DRL、近光、远光、迎宾、亮度等 | 无 |
| `FLM_ZUORDUNG_SENSOREN_KANAELE` | `0xD9FC` | `22` 读 | 物理 LED 通道 ↔ 灯源的对应关系 | 无 |
| `FLM_FUNKTIONSTEST` | `0xA549` | `31` 例程 | LED 大灯功能测试 | 结果表 `RES_0xA549_R` |

推测的请求字节（**未验证**，`31` 例程常需要先进扩展会话 `10 03`）：

```text
FLM_KANAL 启动：      31 01 A5 4B <KANAL> <PWM> <ZEIT>
FLM_KANAL 停止：      31 02 A5 4B            （STPR 无参数，是否支持待测）
按功能点亮：          2E D6 DC <LV 高字节> <LV 低字节> <ZEIT>   （signed int 按 2 字节推测）
读通道对应关系：      22 D9 FC
读通道回读：          22 D6 DB
读功能状态：          22 D7 A7
```

## 3. `LICHTFUNKTION_LV` 中与灯光秀相关的取值

完整表有 78 项，大部分是自适应/矩阵远光的光型。与本项目相关的：

| 值 | 功能 |
| --- | --- |
| `0x33` | 日行灯（Tagfahrlicht） |
| `0x35`–`0x37` | 位置灯模式 1–3 |
| `0x38` | 驻车灯 |
| `0x39`–`0x3D` | **Welcome Light 模式 1–5** |
| `0x3E` | Follow Me Home（伴我回家） |
| `0x40`–`0x44` | **Goodbye Light 模式 1–5** |
| `0x45` | 远光闪烁 |
| `0x49` / `0x4A` | 转向灯闪烁 1 / 2 |
| `0x01`–`0x0D` | 各种近光光型（城市、乡村、高速等） |

## 4. 不要碰的条目

这些条目会改硬件参数、清计数器或触发复位，灯光秀用不到：

- `_LED_CURRENT`（`0x404C`，`2E`）：直接设定 LED 电流 mA，有烧坏 LED 的风险。
- `FLM_HIGHSIDE_SCHALTER`（`0xA550`）、`FLM_KURZSCHLUSS_SCHALTER`（`0xAFF3`）、各种 `*_RESET` / `*_LOESCHEN`。
- 步进电机相关：`_SCHRITTMOTOR_*`、`FLM_POSITION_AHL/LWR`、`FLM_REFERENZIERUNG_SCHRITTMOTOR`。
- `_FUSI_TEST`（`0xF002`）、`STEUERGERAETE_RESET`、`SLEEP_MODE`、`ENERGIESPARMODE`。
- 激光相关：`FLM_FUNKTIONSTEST_LASER`、`STEUERN_SATELLIT_LASER_SICHERHEITSSTATUS_RESET`。激光远光不应进入灯光秀，静止时直射行人有眼睛安全风险。

## 5. 和迎宾灯研究的联系（待验证的假设）

- 功能表里 Welcome Light 和 Goodbye Light 是两组独立功能。v15 实车在约 22 s 出现的第二轮扫动，可能是迎宾灯超时后触发的 Goodbye Light 复用了同一份 Staging 动画，而不是 Staging2 的独立退出程序。可以在停车状态下分别用 `0xD6DC` 点亮 `0x39` 和 `0x40`，对比两者的动画。
- 如果 `2E D6 DC 00 39 …` 能直接播放已编码的迎宾动画，App 就能在停车时**按需播放自定义迎宾动画**，不必锁车/解锁。
- `0xD9FC` 读出的通道表加上 `FLM_KANAL` 单通道点亮，可以把迎宾研究里的 CH01–05 和物理 LED 通道对上号。`LASERINSZENIERUNG 1/2`（激光装饰）很可能就是 CH05 带动的蓝色饰带。

## 6. 建议的实车验证顺序

1. 只读：`22 F1 50` 确认 SGBD；`22 D9 FC` 读通道对应表；`22 D7 A7` 读功能状态。
2. 单通道：静止、P 挡、点火开，用 `FLM_KANAL` 把一个 DRL 通道设成 `PWM 50`、`ZEIT 2`，观察 2 秒后是否自动恢复。
3. 按功能：`0xD6DC` 点亮 `0x33`（日行灯）和 `0x39`（Welcome 1），`ZEIT` 设短值。
4. 测极限：同一通道连续改 PWM，测出从车机发命令到灯光变化的延迟和每秒最多能发几条。
5. 记录 FLM2 是否需要 `10 03`、是否需要安全访问 `27`、是否有新的故障码。

每一步之后读一次故障码（`19 02`），出现新故障就停下。

## 7. 实车只读读数（2026-11-10，FLM Probe 0.1.0）

车辆：车主的 G20 PreLCI 5AZ。点火开、发动机未启动（模块电压 11.5 / 11.6 V）。全部为 UDS `22` 读取，原始文件 `flm_probe_latest.json`。

### 已确认

| 项目 | 结果 |
| --- | --- |
| SGBD | 左 `0F26C0` = `FLM02_L`，右 `0F26D0` = `FLM02_R`。第 1–3 节的布局适用于这台车。 |
| 诊断会话 | `default`。在默认会话下，下面所有读取都被接受。 |
| `DA71` 变体 | `46 3C …`：G20、非 LCI、Automotive Lighting、5AZ Laserlight、ECE 配光，**右舵**。两侧相同。 |
| 迎宾数据 `3009/300A` | 默认会话下可以直接读。两侧 420 字节的 SHA-256 均为 `1ae3a638…59d9`，与仓库内置样例 `factoryShimmer`（G20 2023 EU Original，15 个通道）逐字节一致。也就是说，车上当前刷的是这份 LCI 模板，而不是 2020 Original。 |
| `D7A7` 功能状态 | 每个模块只填写本侧的 24 个字节，另一侧全部为 `FF`。左模块填 L1/L2 组，右模块填 R1/R2 组。 |

### `D9FC` 的数值是物理通道号

SGBD 给 `D9FC` 标的缩放是"÷10"，但实车读到的值是 1–15 的整数，并且和 `D6DB` 通道号一一对应。证据：映射表里 DRL 1/2/3 对应通道 5/6/12，而 `D6DB` 中只有这三个通道的设定电流都是 740 mA。左右两侧的映射完全相同。

| 物理通道 | 映射到的灯源（D9FC） | 读取时 PWM / 电流 / 电压（左；右不同时另注） |
| --- | --- | --- |
| 1 | 转向灯 1 | 0 |
| 2 | 近光 1 / 远光 1 | 80 % / 910 mA / 9 V |
| 3 | — | 0 |
| 4 | 远光 2 | 0 |
| 5 | DRL/位置灯 1 / **激光装饰 1** | 11 % / 740 mA / 19 V |
| 6 | 近光 2 / 远光 3 / DRL/位置灯 2 | 31 % / 740 mA / 12 V |
| 7 | 近光 3 / 远光 4 | 100 % / 910 mA / 9 V |
| 8 | 近光 4 / 远光 5 | 0 |
| 9 | 远光 6 | 20 % / 1000 mA / 6–7 V |
| 10 | 远光 7 | 左 100 %，右 40 % / 1000 mA / 9–10 V |
| 11 | 远光 8 / 激光 1 | 0 |
| 12 | DRL/位置灯 3 | 31 % / 740 mA / 19 V |
| 13–15 | — | 0 |

说明：

- 电流是整数设定值（740 / 910 / 1000 mA），亮度靠 PWM 调节。"电压"一栏是 LED 串的电压，DRL 串约 19 V，高于电池电压，说明模块内部有升压。
- 同一通道对应多个灯源（例如通道 6 同时是近光 2、远光 3 和 DRL 2），说明是共用 LED 串，或者通道在不同功能间复用。具体的电路结构未知。
- 读取那一刻通道 10 左右不同（100 % 对 40 %），可能与右舵的不对称近光配光有关。这只是一次快照，未验证。

### 对迎宾灯研究的影响

- 迎宾数据里的序列 ID **不是**物理通道号：Staging CH01 是近光主增亮层，而物理通道 1 是转向灯；Staging CH02 是 DRL 主层，而物理通道 2 是近光 1。这和交接文档"三套编号不能直接连接"的判断一致。
- 车上实际运行的是 `factoryShimmer`（15 通道），不是 `original2020`（5 通道）。以后拿实车录像和网页比对时，应该加载 `factoryShimmer`。

## 8. 迎宾灯录制（2026-11-10，FLM Probe 0.2.0）

车主在车内开着车机，按下 Record 后用钥匙依次**解锁 → 锁车 → 再解锁**。录制 42.1 秒后手动停止。原始数据：[`data/flm_record_2026-11-10_unlock-lock-unlock.json`](data/flm_record_2026-11-10_unlock-lock-unlock.json)。拟合脚本：[`tools/fit-flm-recording.js`](../tools/fit-flm-recording.js)。

### 采样条件

- 经车机诊断网关读一次 `D6DB`，往返中位数 **302 ms**（268–501 ms）。左右交替读取，每侧约每 0.6 秒一个点（1.4 次/秒）。
- 3 个单位（约 60 ms）的短闪烁看不到。结论只基于较慢的渐变和保持段。
- 每个样本记录发出和收到的时间；拟合时允许真实读数发生在这个区间内的任意时刻。

### 时间线

| 时间（s） | 事件 |
| --- | --- |
| 约 11.6–11.9 | 解锁，迎宾动画开始（拟合起点） |
| 12.2 | 右转向灯闪（物理通道 1） |
| 12.2–13.5 | 通道 5 先弱亮（1–7 % PWM），13.5 s 突然到 96 % |
| 14.3–17.0 | 通道 5 渐暗；通道 12 亮起、闪动 |
| 16.7–18.0 | 通道 2、7、10 **完全同步**地从 0 升到 100 % |
| 18.0–22.2 | 近光保持 100 %，DRL 稳定在通道 5 = 11 %、通道 12 = 31 % |
| 约 23.1–23.5 | 锁车：近光立即熄灭，转向灯闪 |
| 25.1 | 通道 5 再次冲到 95 %，随后通道 12 闪动，28.9 s 全部归零 |
| 约 33.2–33.6 | 再次解锁，和第一次一样完整重放 |

`D7A7` 的 WELL 字节：平时为 `1`，迎宾期间（包括近光保持段）为 `4`，锁车后回到 `1`。

### 拟合结果

模型：把 `factoryShimmer` 的轨道按每单位 T 毫秒展开；亮度按 `PWM = 100 × (亮度/100)^γ` 换算；轨道结束后由车辆自身的稳态接管（迎宾：通道 5 = 11 %、通道 12 = 31 %、近光保持 100 %；告别：全部为 0）。三个事件各自拟合起点。每个 T 都在同样的固定时间窗内比较，约 220 个点。

| 每单位时间 T | 最小平均绝对误差（PWM 百分点） |
| --- | --- |
| 10 ms | 5.18 |
| 16 ms | 2.08 |
| 18 ms | 0.65 |
| **19 ms** | **0.35** |
| 20 ms | 0.44 |
| 21 ms | 0.45 |
| 24 ms | 1.48 |
| 30 ms | 6.94 |

结论：

- **实车有效时间单位约 19–21 ms，10 ms 被排除。** 这是脱离视频、直接由模块读数得到的结果，和车主早先"实车 1× ≈ 网页 0.5×"的观察一致。19 ms 和 20 ms 的差别在 300 ms 采样精度内，暂按 20 ms 处理。
- **PWM 和 Staging 亮度不是线性关系**，γ 约 2.5–3.2（最佳 2.8）。例如 Staging 的 30 % 在 PWM 上只有 3–7 %。网页预览如果想更接近实车观感，可以加一条这样的曲线。

### 物理通道对应关系

| Staging 序列 | 物理通道（D9FC 灯源） | 依据 |
| --- | --- | --- |
| CH01 | 通道 2（近光 1）、7（近光 3）、10（远光 7），三者每个样本都相同 | 245 单位后开始 63 单位的渐亮，和 16.7–18.0 s 的上升吻合 |
| CH04 或 CH05 | 通道 5（DRL 1 / **激光蓝色装饰 1**） | 先到 30 % 亮度保持，再冲到 100 %，然后长渐暗 |
| CH02 或 CH03 | 通道 12（DRL 3） | 先等 90 单位，渐亮闪动，最后渐变停在 30 % |

- CH04 和 CH05、CH02 和 CH03 的形状几乎一样，以现在的采样率分不出来；配对里的另一条可能驱动同一个通道，也可能在这台车上没有对应输出。
- 整个过程中**只有通道 1、2、5、7、10、12 变化过**。通道 6（DRL 2）、8（近光 4）、9 等一直为 0。说明 `factoryShimmer` 里 CH06–0F 这些 LCI 序列在这台 PreLCI 上没有可见输出。
- 这和交接文档的单通道实验一致：CH05 带动蓝色装饰，CH02/CH03 是 DRL 层，CH01 是近光主层。

### 锁车（告别灯）

- 锁车约 1.9 秒后通道 5 冲到 95 %，比拟合起点晚约 94–101 个单位，正好是 CH04/CH05 到达 100 % 的位置。随后通道 12 按 CH02/CH03 的节奏闪动，约 5.4 秒后全部归零。
- 所以**告别灯是从头重放同一份 Staging 数据**，只是 CH01（近光）不运行，结束后不进入 DRL 稳态，而是熄灭。这支持交接文档的推断：Staging2 不是独立的退出程序。
- 解锁后第二轮扫动、约 20 秒计时器等现象，这次录制没有覆盖（第一次迎宾 11 秒后就锁车了）。

### 后续可以改进的地方（仍然只读）

- 只录一侧，或者两侧并发请求，采样率可以翻倍；要分清 CH04/CH05、看到 60 ms 的短闪，需要更快的采样。
- 加载一份**每条序列形状都不同**的测试模板再录一次，就能逐条确认 Staging ID 到物理通道的对应关系。这一步需要用 BimmerCode 写编码，不属于只读实验，由车主决定是否做。
